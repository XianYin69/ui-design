# 需求确认
接收界面设计任务后先澄清，再动手；区分创建 or 修改。
## 必答清单
1. **载体与平台**：Web / 移动 / 桌面 / 大屏；目标分辨率与断点范围。
2. **用户与场景**：主用户画像、关键任务流、使用环境（光照、时长、频次）。
3. **输入/输出**：内容形态与最长文本、数据来源、空态/加载态/错误态期望。
4. **品牌与风格**：既有品牌色/字体/设计系统；参考产品与禁忌风格。
5. **约束底线**：WCAG 等级（默认 AA）、性能预算、素材版权、是否需暗色模式。
6. **验收标准**：可判定的验收判据（对比度数值、点击热区、走查清单）——无判据＝需求未确认。
7. **路径判定**：新界面/新组件 → 创建流程；改既有界面或既有技能 → 修改流程。
## 动作
- 缺项一次一问向用户确认（`ask_user`），禁止用假设填补关键需求。
- 每条判定写逻辑链：`python -B scripts/logic_chain.py add logic_chain.jsonl --from 需求确认 --to <判定> --why <理由>`。
- 存档：`python -B scripts/process_chain.py save --step 需求确认 --data '{"...": "..."}'`。
## 兜底
- 用户不响应或需求持续模糊：出流程/信息架构草图辅助澄清（`scripts/flowchart_helper.py`），仍不明则熔断求助。
