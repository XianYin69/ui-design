# 脚本构建
按大纲与分支裁决产出设计令牌与界面实现；本体薄，规范与范式经依赖获取。
## 动作
1. 脚手架：`python -B scripts/scaffold_design.py --target tmp/<design> --layout tokens,screens,assets,tests`。
2. 令牌：`python -B scripts/design_tokens.py --spec tmp/tokens.json --out tmp/<design>/tokens.css`（单一真源，禁止散落硬编码色值）。
3. 界面实现：调用 [web-design-guidelines](../../../dependence/dependence.md) 取界面准则，
   调用 [frontend-dev](../../../dependence/dependence.md) 取组件实现范式，
   调用 [code-guidelines](../../../dependence/dependence.md) 取命名/注释/复杂度准则。
4. 单文件 ≤50 行：超限即拆「入口 + 模块」，禁止长文件。
5. 静态自查：`lint_check.py`、`layout_lint.py --path tmp/<design>`、`contrast_check.py --tokens tmp/tokens.json`，问题清零才进构建测试。
6. 每步提交功能分支 `feature/<topic>`（见 git 工作流约束）。
## 禁止
- 臆造 API/参数/CSS 属性：任何不确定签名须经 [浏览器学习](../浏览器学习/浏览器学习.md) 取证。
- 使用来源不明素材（见 [素材版权约束](../../../resistance/素材版权约束/素材版权约束.md)）。
- 静默写盘：默认 `--dry-run`，落盘须显式 `--yes`。
