# 构建测试
视觉、无障碍、可用性三类测试全绿才算完成，失败即回脚本构建。
## 动作
1. 构建预览：`python -B scripts/run_tests.py --path tmp/<design> --dry-run` 预览命令，确认后执行。
2. 视觉回归：`python -B scripts/visual_regression.py --path tmp/<design> --baselines tmp/baselines`（断点 320/768/1280 各一遍）。
3. 无障碍：`a11y_audit.py --path tmp/<design>`（对比度、语义标签、焦点顺序、alt、键盘可达）。
4. 布局：`layout_lint.py`（溢出、栅格错位、触控热区 <44px、文本截断）。
5. 可用性：`usability_check.py --flow tmp/outline.md`（关键任务步数、状态完备性、反馈缺失）。
6. 覆盖边界：空态、超长文本、极端数据、暗色模式、低视力和读屏路径。
7. 失败处理：贴最小可复现片段 → `process_chain.py interrupt` → 回 [脚本构建](../脚本构建/脚本构建.md) 修复 → `resume`。
## 产出
- `tmp/test-report.md`：用例数、通过率、失败清单、对比度最低值。
- 逻辑链一条：测试结果 → 是否可交付的裁决。
## 兜底
- 无浏览器/渲染环境：降级为静态令牌与标记审查，并在报告中标注未验证项，禁止以「看起来对」充当通过。
- 重试达 10 次：`penalty.py hit` 熔断，回退本步或求助用户。
