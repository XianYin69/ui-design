# 大纲构建
把设计需求拆成界面结构与令牌，形成可审阅的设计大纲。
## 动作
1. 列界面清单：入口页、核心任务页、状态页（空/加载/错误/无权限）、组件清单。
2. 定信息架构：层级、导航模型、关键任务流步数（超过 3 步须标出可压缩点）。
3. 定设计令牌：色板（含语义色与对比度对）、字阶、间距栅格、圆角、阴影、动效时长。
4. 定交互契约：焦点顺序、命中区尺寸、反馈时机、键盘与读屏路径。
5. 标风险点与待验证假设（供分支分析与浏览器学习消费）。
6. 大纲交用户审阅确认后再进入分支分析；确认结论写逻辑链。
## 产出
- `tmp/outline.md`：界面表 + 令牌表 + 任务流 + 风险清单（≤50 行，超则拆子文档）。
- 每界面一条 `process_chain.py save --step 大纲构建 --data '{"screen":"..."}'`。
## 兜底
- 大纲与需求冲突：回 [需求确认](../需求确认/需求确认.md) 重澄清，禁止私自缩减范围。
- 规模过大：先交 MVP 界面子集，其余列 TODO 并告知用户。
