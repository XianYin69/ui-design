# 分支分析
对大纲的每个岔路做正反双链自辩，再定平台/风格/组件库分支。
## 分析维度
1. **载体分支**：响应式 Web / 原生移动 / 桌面；断点策略与输入方式（触控 vs 指针）。
2. **风格分支**：极简/新拟物/玻璃拟态/品牌拟物；与品牌资产、可读性、实现成本的取舍。
3. **组件库分支**：无依赖手写 / 既有设计系统 / 第三方库（维护状态、许可证、体积、可定制度）。
4. **排版分支**：系统字体栈 / 自托管字体 / 商用字体授权；字阶与行高对长文可读性的影响。
5. **风险分支**：对比度不足、触控热区过小、暗色模式反色、动效致前庭不适、超长文本溢出、RTL。
## 动作
- 每个岔路一次辩论：`python -B scripts/logic_chain.py debate --pro <正方> --con <反方>`，裁决记逻辑链。
- 结论落 `tmp/branch-decision.md`：选项、裁决、理由、被否方案。
- 任一维度信息不足 → 立即转 [浏览器学习](../浏览器学习/浏览器学习.md)。
## 兜底
- 双链势均：选无障碍代价更低、可回退性更强的一支，并记 TODO 复验。
