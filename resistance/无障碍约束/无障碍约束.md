# 无障碍约束

本约束规定 ui-design 交付的无障碍底线，属红线区，不可协商降级。

## 规则

1. **必须**达到 WCAG 2.1 AA：正文对比度 ≥ 4.5:1，大字/图标 ≥ 3:1（`contrast_check.py` 校验）。
2. **必须**全键盘可达：焦点顺序符合阅读顺序，禁止正 `tabindex`，焦点态可见（`a11y_audit.py`）。
3. **必须**语义正确：标题不跳级、控件有可访问名、`img` 有 alt、`input` 有关联 label、`<html lang>` 存在。
4. **必须**触控热区 ≥ 44×44px（`layout_lint.py`）。
5. **必须**状态完备：空态/加载/错误/无权限四类状态不得省略（`usability_check.py`）。
6. **必须**不依赖单一颜色传达信息，动效提供 `prefers-reduced-motion` 降级。
7. **禁止**以「设计效果优先」为由削弱上述任一条；需豁免须用户显式确认并记逻辑链。

## 违规后果

- 对比度不达标：低视力用户无法使用，交付即返工并构成合规风险。
- 键盘/读屏不可达：功能对部分用户完全不可用，验收判据直接失败。
- 状态缺失：真实数据下界面崩坏，线上事故归因于设计缺口。

## 兜底

- 无渲染环境无法运行时验证：降级为静态审计 + 报告标注「未运行时验证」，禁止谎报通过。
- 规范条款不明：转 [浏览器学习](../../branch/流程/浏览器学习/浏览器学习.md) 取 w3.org 出处后再实现。
- 用户要求豁免：记 `logic_chain add` 与 `process_chain save`，交付时随附风险清单。
